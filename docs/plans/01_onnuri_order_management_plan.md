# 온누리스토어 발주 및 거래명세서 관리 시스템 구현 계획서

## 1. 개요
본 프로젝트는 제니트리가 온누리스토어(무신사 뷰티)에 납품하는 11종 화장품의 발주서를 관리하고, 거래명세서를 간편하게 출력할 수 있도록 지원하는 웹 애플리케이션입니다. 

## 2. 사용 기술 및 환경
- **프론트엔드**: React, Vite
- **상태 관리 및 저장**: LocalStorage 또는 IndexedDB (별도의 서버 없이 브라우저 내 데이터 보관)
- **엑셀 파싱**: `xlsx` (SheetJS)
- **디자인 시스템**: 제니트리 디자인 시스템 v5.0 (`jt-core.md` 엄수)
- **배포 환경**: Cloudflare Pages (정적 SPA 배포)

## 3. 핵심 기능 구현 계획

### 3.1 발주서 자동 인식 및 파싱
- 파일 업로드 UI를 통해 `온누리스토어_무신사뷰티_발주서_(주)제니트리_YYMMDD.xlsx` 파일을 업로드합니다.
- 파일명에서 정규식을 이용해 `YYMMDD`를 추출하여 '발주일자'로 인식합니다.
- 발주서 내부의 "품목" 행(약 26번째 행)을 찾아 그 아래의 데이터(제품명, 수량, 입고일 등)를 추출합니다.

### 3.2 품목 및 단가 매칭
- 물품등록서(`물품등록서_제니트리_온누리스토어_260819.xlsx`) 데이터를 앱 내부에 기본 데이터(JSON 형태)로 내장하여 매칭 속도를 높입니다.
- 단가 기준은 **공급가(권장 소비자가의 45%)** 로 고정합니다.
- 화면 상단에 '소비자가 숨기기' 토글 버튼을 배치하여, 체크 시 표에서 소비자가 열이 사라지도록 구현합니다.

### 3.3 대시보드 및 발송 관리
- **목록 뷰**: [발주일자], [원본 파일명], [납품일자], [발송방법/송장번호], [상태/출력] 열을 제공합니다.
- **발송방법 및 송장번호**: 각 행에서 드롭다운(대한통운, 직접배송 등)을 선택하고, 송장번호를 텍스트로 입력하면 로컬 스토리지에 자동 저장됩니다.
- 상태 표시는 색상뿐만 아니라 반드시 글자 배지(`.jt-badge`)를 병기합니다. (예: `[대기]`, `[발송완료]`)

### 3.4 명세서 인쇄 (출력)
- 대시보드에서 '명세서 출력' 버튼 클릭 시, 인쇄용 레이아웃이 적용된 모달 또는 새 창이 뜹니다.
- 브라우저의 기본 `window.print()`를 호출하며, 인쇄 시 CSS `@media print`를 활용해 불필요한 UI(버튼 등)를 숨기고 명세서 양식만 깔끔하게 출력되도록 설정합니다.

## 4. UI/UX 디자인 가이드라인 준수 (jt-core)
- **에셋 및 토큰**: 외부 CDN의 `jt-tokens.css`와 `jt-utilities.css`를 `index.html`에 연동합니다.
- **버튼 색상**: 저장, 출력 등 주요 액션 버튼은 파란색이 아닌 Charcoal(`--color-primary`)로 지정합니다. 파란색(`--color-accent`)은 링크나 포커스 등에만 제한적으로 사용합니다.
- **테이블**: 모든 데이터 표는 `<div class="jt-table-wrap">`으로 감싸고, 금액 및 수량 데이터는 `<td class="jt-num">`을 적용하여 우측 정렬합니다.
- **금지 사항**: `#hex`, `px` 단위, Tailwind의 임의값 대괄호 표기를 절대 사용하지 않고 `var(--jt-*)` 토큰만 사용합니다.

## 5. 배포 전략 (Cloudflare Pages)
- `npm run build` 명령어로 생성된 `dist` 폴더를 Cloudflare Pages에 배포할 수 있도록 세팅합니다.
- 새로고침 시 404 에러 방지를 위해 Cloudflare `_routes.json` 또는 `wrangler.toml`의 SPA 라우팅 설정을 가이드에 포함하여 제공합니다.

## 6. 진행 순서
1. React + Vite 기본 프로젝트 생성 및 디자인 시스템 CSS 연동
2. 엑셀 파싱 로직 및 물품 매칭 유틸리티 구현
3. 대시보드 화면 및 발송방법/송장번호 입력 폼 구성
4. 거래명세서 팝업 및 인쇄 모드 구현
5. 전체 UI 자가 점검 (jt-core 6항목 기준)
6. Cloudflare 배포 설정 파일 작성 및 안내

> **제니 확인 요청**
> 데이터베이스(DB) 서버를 따로 구축하지 않고, 브라우저의 저장소(IndexedDB/LocalStorage)를 활용하는 방식으로 진행해도 괜찮을까요? 여러 컴퓨터에서 공유해야 한다면 백엔드(Supabase 등)가 필요할 수 있습니다. 현재 계획대로 로컬 저장소 기반으로 가볍게 시작할까요?
