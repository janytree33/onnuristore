# 03. 온누리스토어 B2B 발주/납품 관리 시스템 개편 계획서

## 1. 개요
기존 쇼핑몰(B2C) 형태의 UI(장바구니, 본인구매 등)를 제거하고, 본래 사용 목적에 맞는 **기업 간 거래(B2B) 발주 내역 파싱 및 출고 이력 관리**에 최적화된 시스템으로 전면 개편합니다.

## 2. 주요 변경 사항

### 2-1. 화면 구성(UI) 분리
메인 화면을 두 가지 탭(또는 메뉴)으로 분리하여 목적을 명확히 합니다.

1. **기준정보 탭 (마스터 데이터)**
   * 복지몰의 깔끔한 카드형 디자인은 유지하되, **장바구니 및 구매대상 선택 기능은 완전히 제거**합니다.
   * 품목명, 이미지, 전자라벨 링크, '온누리 납품가(45%)' 정보만 명확하게 조회할 수 있는 카탈로그 형태로 전환합니다.

2. **발주/출고 관리 탭 (핵심 기능)**
   * **엑셀 업로드 & 파싱**: 온누리스토어 발주서(엑셀)를 업로드하면 데이터를 추출합니다. 이때 파일명 끝의 YYMMDD를 '발주일자'로 자동 인식합니다.
   * **DB 영구 저장**: 파싱된 데이터를 단순히 화면에 띄우지 않고 Supabase 데이터베이스에 저장하여 이력을 관리합니다.
   * **출고(납품) 이력 관리**: 저장된 발주 목록에서 '발송 방법(예: 택배)'과 '송장번호'를 입력하고 수정할 수 있는 기능을 제공합니다.
   * **거래명세서 출력**: 개별 발주 건 또는 일자별 발주 건에 대해 [명세서 출력] 버튼을 제공하여, 인쇄용 거래명세서 팝업/화면을 띄웁니다.

### 2-2. 데이터베이스(Supabase) 설계
발주 이력 관리를 위한 신규 테이블을 생성합니다.

* **테이블명**: `onnuri_orders`
* **주요 컬럼**:
  * `id` (고유번호)
  * `order_date` (발주일자 - 파일명 추출)
  * `product_name` (품목명)
  * `quantity` (발주수량)
  * `supply_price` (공급단가)
  * `total_amount` (합계금액)
  * `shipping_method` (발송방법 - 기본값: 택배발송)
  * `tracking_number` (송장번호)
  * `status` (상태: '발주등록' -> '출고완료')
  * `created_at` (등록일시)

### 2-3. 개발 원칙 적용 (사용자 규칙)
* **모달(Modal) 사용**: 브라우저 기본 팝업(window.alert 등) 대신, `src/components/modals` 내부에 앱 스타일과 어울리는 자체 모달을 제작하여 알림과 입력을 처리합니다.
* **UI 에셋 중앙 관리**: 버튼 및 아이콘은 하드코딩하지 않고 디자인 시스템 토큰과 `uiAssetService`를 연동하여 사용합니다.

## 3. 진행 단계 (Step-by-Step)
1. **[DB 연동]** Supabase에 `onnuri_orders` 테이블 생성 쿼리 작성 및 적용
2. **[UI 개편]** `ItemList.jsx`를 탭(기준정보/발주관리) 형태로 개편하고 장바구니 기능 제거
3. **[엑셀 & DB]** 엑셀 업로드 시 파일명에서 날짜를 추출하여 파싱된 데이터를 DB에 Insert 하는 기능 구현
4. **[출고 관리]** 발주 내역 리스트에 송장번호 입력칸 및 [거래명세서 출력] 버튼 추가
5. **[명세서 인쇄]** 거래명세서 인쇄용 화면/레이아웃(A4 최적화) 모달 또는 새 창 구현
